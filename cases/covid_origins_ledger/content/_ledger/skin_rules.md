# Subject-specific writing rules (the "skin")

The universal rules — the bored reader test, paragraph architecture, no self-narration,
mechanism-over-apparatus, source discipline, voice, and the hard gates G0–G4 — live in the
shared `skill-ledger-write` assistant. **This file holds only the rules specific to THIS
subject.**

`skill-ledger-bootstrap` drafts a first version from your subject and your named reader; you
prune and sharpen it, and it grows as new failure modes surface.

Worked example — the Quantum KE white paper's pack:
- **W1** dual-audience register (a policy so-what AND scientific defensibility in every section)
- **W2** no-hype ladder (label every claim demonstrated / plausible / aspirational)
- **W3** primary-source-for-policy (legislation / official report / paper, never news)
- **W4** honest-on-region (surface genuine touchpoints; never manufacture a national narrative)
- **W5** progressive disclosure (plain main line; technical depth in callouts / appendices)

## This subject's rules — COVID-19 origins, the furin-cleavage-site (FCS) question

The subject is a **live scientific disagreement**. The job is to MAP the argument faithfully with
verified quotes, not to adjudicate it. Every rule below serves that neutrality.

- **C1 symmetric mapping** — model BOTH the natural-origin and the lab-origin / engineering-leaning
  positions with each side's OWN verbatim quotes. Never state a conclusion the sources do not, and
  never let one side's claim stand as the narrator's voice. **[gate]**
- **C2 quote-pinned characterisation** — any claim that a statement is rhetorical, overstated, or
  "performed certainty" must pin to a verbatim span via an assessment record (`Assess-rhetorical`).
  A characterisation with no quoted span is an opinion, and opinions do not travel. **[gate]**
- **C3 independence before agreement** — when two sources reach the same FCS conclusion, look for a
  SHARED premise first (`Correlated-with`); two papers leaning on the same rarity assumption are not
  two independent data points. Let the derived double-count finding stand; do not hide it.
- **C4 crux-first** — for the FCS sub-question, name the crux (the claim whose resolution would
  actually settle it) before logging supporting/rebutting detail, so the reader sees the hinge.
- **C5 settled vs performed** — distinguish a question the field has SETTLED from one where
  consensus is *performed* over an open crux; a `Status: performed-settling` must name that crux.
